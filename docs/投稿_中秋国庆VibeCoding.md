## 一、作品是什么

**走啊！** 是一个为「临时起意出门」做的自驾决策工具。

出发前先说一句你能接受多远（30 分 / 1 小时 / 2 小时 / 3 小时车程），点一次「走啊」，它就以你的位置为中心向四周扫一圈，用真实路况反演出**哪个方向现在不堵、周边哪片区域人少**，再从那个方向里挑出具体能去的地方，一键跳转高德导航。

一句话：高德告诉你"别走这条路"，走啊告诉你"走哪个方向"。

## 二、灵感来源

来自我自己的真实场景，不是命题作文。

假期里经常是**临时起意想出门转转，又担心人多，不知道去哪里好**。真要认真选，就得来回对比好几个目的地的距离、路况、人多不多——**找了几个以后，已经不想走了**。

更常见的是这两种情况：

- 本来没打算出门，但在家待腻了，想出去走走；
- 带娃，没法提前安排长时间出行，只能看当下情况临时决定。

这两种情况下，"想去哪"根本没有答案。需要的是一个**当下就能给出方向**的工具，而不是让我自己做一轮调研。

市面上的导航都是"你已经决定去哪了，我帮你走"，没人解决"我还没决定去哪"。

## 三、它解决了什么假期问题

假期出门的麻烦几乎都集中在「还没决定去哪」这一步。走啊把这个决定反过来做，不让你先选目的地：

- **临时起意，没有目的地**——不要求你输入目的地，只要求你在哪，其余交给扫描。
- **逐个对比太费时间，选完就不想动了**——一次扫描直接给出 Top-3 区县和方向，不用自己做一轮调研。
- **怕撞上人挤人**——用真实通行速率反演拥堵程度，指数越低代表人越少，颜色一眼可辨。
- **带娃、时间不确定，长行程安排不了**——出发前先定「最远车程」，超出这个时长的区县直接不进推荐，不会推给你一个开车两小时的地方。
- **选完还得再切导航**——一键跳转高德导航，`uri.amap.com/navigation`。

## 四、作品截图

（发帖时在此处插入 3 张截图，依次是：出发前 / 扫描中 / 结果）

1. **出发前**：地图主舞台 + 「最远车程」选择 + 「走啊」按钮。如果没授权定位，会弹出应用内的出发地兜底浮层，可以直接点城市或输入出发地，不用先做一堆设置。
2. **扫描中**：以你的位置为中心逐扇区点亮，扇区颜色由真实通行速率换算，越堵点亮越慢，热力底图同步铺开。
3. **结果**：热力扇区 + Top-3 推荐区县，每张卡带方向、人少/正常/人多、距你多少公里、车程约多少分钟、区内代表景点，点进去还能看这个区县能去哪。

截图在本地开发环境（`npm run dev` 后打开 `http://localhost:5173`）实拍，页面上的数据都是高德真实返回。

## 五、用 TraeCode 的创作过程

（此处插入 2-3 张 TraeCode 过程截图：对话/代码/验证）

关键步骤：

1. **先定产品边界**：明确"不做第二个导航"，只解决"还没决定去哪"，把产品定位收敛成一句话，避免功能发散；
2. **数据链路先行**：先打通高德真实接口（驾车路径规划 / 行政区划 / 逆地理编码 / POI），拒绝用假数据演示，能跑真数据再谈界面；
3. **把配额当约束来设计**：高德有 QPS 与调用量限制，所以做了前端请求队列（并发上限 3）+ 服务端节流，扫描一轮控制在 12 次调用量级；
4. **降级要显式**：定位失败、规划失败、配额耗尽、断网四种情况都给了明确反馈，宁可说"没扫出方向"也不伪造数据；
5. **写测试替代人工回归**：把 router 做成可注入的，用「堵城 / 空城 / 跨城远景」三类替身跑场景回归，不消耗真实配额。

## 六、技术说明

- H5 前端（移动端优先）+ 高德 JS API + Canvas 热力自绘
- 高德 Web 服务 Key 只存在于服务端代理，不入前端、不入仓库
- 31 项单测全过，覆盖扇区指数反演、队列并发峰值、多城市场景回归、可接受车程过滤
- 全部视觉值收敛为设计 Token（CSS 变量），组件层不硬编码
