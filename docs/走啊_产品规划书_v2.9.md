## 1. 项目背景与目标

### 1.1 背景
双节（中秋+国庆）是全年自驾出行峰值，"临时起意去哪"这个决策时刻没有任何数据工具服务。本作品用高德开放平台公开API构建一个"反向导航"产品：不回答"怎么去"，回答"去哪"。

### 1.2 双目标
| 目标 | 说明 | 优先级 |
|---|---|---|
| 活动获奖 | TRAE社区中秋国庆VibeCoding优秀作品奖（100元京东卡+电脑包）或积极创作奖（30元京东卡） | 本期 |
| 个人作品沉淀 | 可写进个人作品集/简历的完整产品案例（从需求验证到算法到落地），作为副业资产化的能力背书 | 长期 |

注意：本产品为一次性参赛作品，**不承诺长期商业化**（见第16章风险）。

### 1.3 交付物
- 可运行的Web应用（H5，移动端优先）
- TRAE社区作品帖（截图+GIF+体验链接+创作过程）
- 本规划书（开源一并发布，作为创作过程展示）

### 1.4 成果形态与发布策略（v2.4 新增）
> 决策：**本期只做 H5 Web；App 明确不做；微信小程序列为 V2 可选方向**。形态选择直接决定地图方案与合规路径，详见下表。

| 形态 | 结论 | 核心理由 |
|---|---|---|
| H5 Web（本期） | ✅ 唯一形态 | 零审核、个人主体无门槛、高德 JS API 全能力（热力自绘/路况图层/跳高德导航顺畅） |
| 原生 App | ❌ 不做 | 双端开发 + 商店审核 + 分发获客，对轻量决策工具是纯负资产 |
| 微信小程序（V2） | ⭕ 可选加分 | 微信内即扫即用、契合"分享卡发家庭群"；但有两个硬门槛（下） |

**小程序落地前的硬门槛（V2 时点复核）**：
1. **AI 合规**：涉及 AI 问答需【深度合成-AI 问答】类目，**仅企业主体开放，个人主体不可**；自研需《互联网信息服务算法备案》，第三方需技术方算法备案 + 双方合作协议（或《在用证明》），且资质主体须与小程序注册主体一致 → 故**推荐语一律高德 POI 数据模板化生成，不接 LLM**，从源头规避深度合成类目。
2. **地图绑定**：微信 map 组件基于腾讯地图；高德 JS API 自 2023 年起禁止非 Web 端 key 调用，小程序只能用高德小程序 SDK（仅数据接口、无高德底图）→ 地图切**腾讯位置服务**或"高德数据 + 腾讯底图"混合；小程序内无法直接导航，需拉起外部地图 App（微信内受限）。
3. **类目与域名**：旅游类目下纯"景点推荐/景区服务"免资质（涉预订/售卖需《旅行社业务经营许可证》）；外部 API 需在后台配置 request 合法域名（HTTPS）。

一句话：**H5 打天下（本期）→ 小程序拓分发（V2，企业主体、模板化内容、腾讯地图）→ App 不碰。**

## 2. 设计哲学

1. **决策层，而非导航层** — 所有导航产品回答"怎么去"（前提是有目的地）；我们回答"去哪"，在临时起意的决策时刻用实时路况反向推导方向。
2. **数据诚实** — 产品内每个数字（拥堵等级、通行时间、节省分钟数）都来自高德真实接口，不造假、不填充演示数据。评委问"数据哪来的"，直接指向接口文档。
3. **反向思维产品化** — 不发明新数据，发明新用法：同一套公开API，把"躲避拥堵"反转成"发现低拥堵方向"。
4. **一屏一决策** — 不做信息仪表盘，不做多层筛选。打开 → 扫描 → 2~3条明确建议 → 走人。每页只服务一个决策动作。
5. **克制的炫技** — 全产品唯一的表演是雷达扫描动画（扇区逐个点亮），它同时是品牌记忆点和API节流的天然遮罩。其余交互全部服从信息效率。
6. **自驾语境统一** — ETA、路线对比、节省分钟数全部按驾车场景计算；离开"车"，路况信号即失效，产品不服务公共交通用户。

## 3. 市场背景与竞品分析

| 层级 | 现有产品 | 结论 |
|---|---|---|
| 实时路况展示 | 高德App自带红绿黄路况；开发者可用 `AMap.TileLayer.Traffic` 一行代码挂载官方图层 | ❌ 不做重复，仅作底图参照 |
| 人流热力 | 高德App"环境地图"有，但API不开放；腾讯位置大数据只能看不能调；商用客流API（及刻等）按围栏收费 | ❌ 放弃，以车流为代理信号 |
| 躲避拥堵导航 | 高德/百度/腾讯导航标准能力，前提是目的地已定 | ❌ 不碰，作为结果页跳转出口 |
| **无目的地的错峰决策** | **空白** | ✅ **本产品唯一战场** |

**结构性空白的原因**：导航产品的商业逻辑绑定"目的地明确、立即出发"的场景，"还没想好去哪"这一步不产生导航调用量，是大厂盲区——不是技术难题，是动机缺失。

**一句话竞品定位**：高德告诉你"别走这条路"，走啊告诉你"走哪个方向"。

## 4. 需求验证（小红书田野调查，2026-09-22）

立项前对"临时出行"需求的快速验证。结论：**需求真实存在，且用户已自发演化出"人肉版『走啊』"**。

### 4.1 量化证据：临时出行是大盘（表述已校准，见 4.6 备注）
携程周边游数据（央广网/人民网转引）：小长假提前0~2天下单的订单占18%——表明"出发决策越拖越近"是普遍趋势。**该口径应解读为"出发前1~2日才确定行程的订单比例"**，而非精确的"当天临时起意比例"；叙事用"约1/5订单临近期才确定"，避免夸大因果。

### 4.2 小红书笔记生态：临时起意周边游是成熟内容类型
- 亲子家庭：杭州妈妈带6岁娃，"周一早上7点，临时起意、娘俩说走就走"，三天两晚
- 家庭自驾：天津一家三口"临时起意"自驾济南，当晚看灯会凌晨返
- 情侣/好友：呼和浩特用户"临时起意，果断选择距离呼市只有一个小时车程的九龙湾"
- 汽车社区中"临时决定周边游"已是电车续航测评的标准场景话术

### 4.3 最强信号："听劝式旅行" = 人肉版「走啊」
2024年爆火：年轻人**上车后才发笔记**《马上到武汉！！听劝！！！！》，把"去哪、吃什么、玩什么"全部外包给评论区，单帖248条评论全是本地人建议。
- 行为模式：先出发、再决策、用社区人肉API填补决策空白
- 启示：用户不是不需要决策工具，是只能用极低效替代方案解决。**当用户开始用UGC人肉模拟一个工具时，就是该工具最真实的PMF证据。**
- 远期空间：存在"轻社区层"想象空间（V2方向，Demo不做）。

### 4.4 避堵决策真实存在，但依据滞后
真实案例：一家人国庆原定去重庆，"看到新闻里说景区到处是人，就立马改了行程"改去广西。决策动作真实，但依据是滞后新闻而非实时路况——走啊的升级点。

### 4.5 反向教训：半径假设被验证
行业分析：周边游可"说走就走"，跨区域旅行很难（大交通需提前预订）。
→ 60km默认半径正确；**产品叙事禁用"说走就走旅行"，统一用"周边临时起意出行"**。

### 4.6 验证小结
| 验证假设 | 结论 | 备注 |
|---|---|---|
| 临时起意出行是否普遍存在 | ✅ | 约1/5周边游订单为临近期决定（口径见4.1） |
| 决策时刻是否有工具 | ❌ | 空白，被"听劝帖"人肉填补 |
| 避堵/避人流决策是否存在 | ✅ | 存在，但依据滞后 |
| 60km周边半径是否合理 | ✅ | 符合临时出行真实半径 |
| 核心人群是否自驾 | ✅ | 案例以自驾为主，车流信号成立 |

## 5. 面向人群

### 5.1 Persona 1：自驾亲子家庭（核心人群，占比预估50%+）
- 特征：有娃（学龄前~小学），家庭自驾；假期只能临时起意；孩子受不了长时间堵车；决策窗口短（出发前一小时内）
- 诉求："一小时车程内，哪个方向现在不堵？到了能玩什么？"
- 设计响应：大字分享卡（发家庭群）、扫描结果快、信息密度低

### 5.2 Persona 2：年轻自驾/情侣（传播人群）
- 特征：追求"反向旅游"、小众出片地；厌烦网红景点排队；活跃于小红书
- 诉求："今天哪里冷门又值得去？给数据支撑，不要给感觉。"
- 设计响应：分享卡颜值高、有"冷门认证"话术、可自传播

### 5.3 Persona 3：自驾返乡+短途混合人群（次级人群）
- 特征：国庆自驾返乡（或返乡后用车），中途想顺路停留；不熟悉家乡周边路况
- 诉求："返乡路上顺路去哪不堵？"

### 5.4 非目标用户（明确不做）
| 人群 | 不做原因 |
|---|---|
| 高铁/飞机等公共交通出行者 | 路况数据（车流信号）对他们是噪音，产品核心逻辑不成立 |
| 已有明确目的地的用户 | 属导航层，高德已覆盖，跳转出口即可 |
| 跨城长途旅行者 | 大交通需提前预订，不存在"临时起意"决策时刻 |
| 无车但打车出行的用户 | 灰色地带：技术上可用（路网相同），但Demo不单独优化 |

## 6. 痛点描述

### 6.1 决策时刻的黑暗
节假日出行真实流程：出发前30分钟，家庭群里问"去哪？"，然后刷朋友圈、翻小红书、问同事——全是过时或片面的碎片信息。没有工具能回答"以我家为圆心、此刻、哪个方向是绿的"。

### 6.2 拥堵是方向性问题，不是路线性问题
导航能帮你绕开一条堵路，但绕不出一个堵死的方向——整个东南方向景区全部饱和时，所有"躲避拥堵"都在局部打转。用户需要的是**换一个方向**的决策依据。

### 6.3 "反向旅游"风潮没有数据工具
冷门县城游成为风潮，但"哪里冷门"靠口口相传；小红书推文火了，那里也不冷门了。实时路况（车流的先行指标）是"冷门程度"最诚实的代理信号——**路上没车的地方，大概率还没火**。

### 6.4 现有产品的结构性忽视
大厂盲区，详见第3章。

### 6.5 用户已在用人肉方案自救
"听劝式旅行"证明决策空白真实存在，且用户愿意付出极高成本（发帖、等评论、人工筛选248条回复）解决它。

## 8. 核心算法：扇区反向扫描

> **状态标注（v2.8）**：本算法原按「交通态势矩形查询」设计，但 12.4 前置验证判定交通态势**个人不可用**（高级服务接口需商务咨询），故**当前数据主路线为 9.6-方案2「路线级代理」**（对候选锚点调驾车路径规划，以 ETA/路程速率比反演方向拥塞度，见 8.4）。本章保留为商务申请获批后的升级路径。

```
输入：定位点P，半径R=60km（可调至150km），扇区数K=12（每30°）
距离衰减权重：w(d) = 1/(1+d/20)（远处拥堵与我关系小）

1. 生成12个扇区，每扇区沿中轴线取3个检查点（10km / 25km / 45km）
2. 每个检查点：交通态势API查询 5km×5km 矩形
   → 拥堵等级分布（畅通=1 / 缓行=2 / 拥堵=3 / 严重拥堵=4，取均值）
3. 扇区拥堵指数 = Σ(检查点评分 × w(距离)) / Σw，归一化到 0~100
4. 县区聚合：检查点反查所属县区（行政区API，本地缓存）
   → 县区热度 = 扇区内检查点均值 → 地图边界+填色渲染
5. 推荐候选：取拥堵指数最低的2~3个扇区
   → 扇区内选锚点（优先预置底库景点，否则县区几何中心）
   → 路径规划（驾车）验证 → ETA、里程
6. 对比输出：vs 最高拥堵扇区同距离路线的ETA差 → "节省X分钟"（口径见8.3）
7. 推荐理由（模板生成，不调LLM）：
   "正北方向当前畅通 · 途经X县全绿 · 比热门方向节省47分钟"
```

### 8.1 工程要点
- 扫描动画时长6~8秒 = 真实API节流时间（检查点分批并发，QPS≤3）
- 扫描结果缓存5分钟，重复进入直接读缓存
- 查询失败降级"演示模式"（本地缓存历史数据+明确标注）

### 8.2 算法已知局限（诚实披露）
- 路况≠人流：某县全绿可能只是因为没人去（这正是我们要的"冷门"）也可能是景点关闭——文案标注"以车流为冷清度代理信号"
- 检查点是采样而非全量：扇区指数是估计值，够用但非精确；且靠近圆心的相邻扇区检查点方框（5×5km）可能有轻微重叠，指数为"估计的排序依据"，不追求绝对精确
- 路径规划ETA是动态值：结果页标注"路况随时变化，出发前请复核"

### 8.3 "节省X分钟"对比口径（v2.1新增，明确边界）
"节省X分钟" = **最低拥堵扇区 vs 最高拥堵扇区，各自到其锚点的 ETA 差**；两者目的地不同、路线不同，该数字仅用于**相对排序**（帮你更快下判断），**不承诺"绝对少堵X分钟"**。

> 结果卡呈现处理：数字仍以大字突出（决策效率优先），但卡片底部附一行小字说明：
> "该数值为错峰方向与最热门方向（目的地不同）的ETA对比，用于帮你取舍方向，不代表绝对通行时间。" + 数据时间戳"本次扫描于 X 分钟前"（缓解判断依赖）。来源标注不造假原则（见第2章设计哲学）。

### 8.4 路线级代理算法（v2.8 新增，当前数据主路线；v2.9 真实数据实测跑通）
> 依据 12.4 实测：交通态势个人不可用（高级服务接口需商务咨询），数据主路线切换为**「路线级代理」**——用个人可用的驾车路径规划（`strategy=12` 躲避拥堵）反演方向拥塞度，全国覆盖、无城市限制。
>
> **v2.9 实测结论**（杭州中心 + 4 真实锚点，个人 key）：3 个方向真实返回 distance/duration，速率反演出方向差异——天目山 60.9km/h、云上草原 53.6km/h、莫干山 50.2km/h，中位数基准后莫干山方向拥塞指数最高（idx 6），算法正确区分拥堵方向；第 4 个请求触发 `CUQPS_HAS_EXCEEDED_THE_LIMIT`（账号 QPS 限流），实证 **9.2/10.6 的 QPS≤3 队列化与重试**的必要性。200-299 级接口（direction/driving、district、geocode）均实测可用。

```
输入：定位点 P，半径 R=60km（可调至150km），扇区数 K=12（每30°）

1. 候选锚点集：预置景点底库（data/destinations.json）+ POI 按需补充（9.7），
   按方位角（0~360°）归类到 12 扇区
2. 每扇区取代表性锚点（底库 POI 优先，否则县区中心），调驾车路径规划：
   - strategy=12（躲避拥堵，多路径中取最优）
   - strategy=2（常规最快，作基准对照）
   → 得 ETA（duration）与里程（distance）
3. 扇区通行速率 V_sec = distance / duration（km/min）→ 方向"速度比"
4. 扇区拥塞指数（相对基准，0~100）：
   idx = clamp( (V_ref − V_sec) / V_ref × 100, 0, 100 )
   V_ref = 全扇区实测速率中位数（相对基准消解城市间绝对速度差异）
5. 县区热度 = 该县区所属扇区指数（县区边界来自行政区划接口，承 9.6-方案2/12.4-第4项）
6. 推荐候选：指数最低的 2~3 个扇区 → 锚点路径规划验证 → ETA / 里程
7. 对比输出：vs 最高指数扇区同锚点路线 ETA 差 → "节省X分钟"（8.3 口径不变）
8. 推荐理由（模板生成，不调 LLM）：
   "正北方向通行最快 · 途经X县 · 比热门方向节省47分钟"
```

**约束（审计门禁）**：
- 调用量：每候选双策略 = 2 次路径规划；Top 候选 6~8 次/扫描，适配 9.2 配额（注册后复核实际值）
- 速率比是**相对指标**：只做方向间排序，不做绝对速度承诺（承 8.2 诚实边界）
- 全国覆盖：路径规划无城市限制 → 12.2 实测城市清单（含连云港）全支持
- 缓存：同一（P, 锚点）5 分钟内重复扫描零新调用；scanned_at 时间戳照常刷新

### 9.3 Key安全
- Web服务Key必须在服务端调用，禁止裸奔前端
- 活动期演示可临时前端直调，但使用独立Key，随时可撤销
- 上线正式版必须加Proxy（可用 Serverless 函数，零成本起步）

- 全链路统一GCJ-02（高德坐标系），不混用GPS原始坐标（WGS-84）
- H5 geolocation返回WGS-84，必须经转换后再查询

### 9.5 前置性数据风险验证（v2.1新增，9/22当日完成）
本产品78%的核心价值依赖「交通态势」接口与「躲避拥堵」路径策略，二者对**个人开发者**的开放性与配额未经实测，属单点死穴。**必须在本日完成验证后，核算法才能成立。** 对应可执行清单见第12.4节。

### 9.6 数据源备选预案（v2.1新增，仅当 9.5 判定不可用时启用）
若「交通态势」对个人开发者不可用或配额过小，择优切换（按可行性排序）：
1. **官方实时路况图层视觉化替代**：`AMap.TileLayer.Traffic` 仅作底图可视，无法回读数值 → 用「行政区划」+ 预置底库生成"结构性冷门"排名（牺牲实时性，保真实）。
2. **路线级代理**：对候选锚点逐个调「驾车路径规划」拿 ETA，以"ETA/路程 速率比"反推该方向通行速度，拟合拥塞度（依托 5000次/日 配额，最稳）。
3. **声明降级**：明确标注"实时路况在个人版不可用，本Demo以地理冷门度演示逻辑"——诚实降级，不造假货（守住第7.3下界）。

### 9.7 目的地信息数据源（v2.4 新增，单一数据源决策）
> 结论：目的地介绍与旅游资源的**唯一数据源 = 高德开放平台 POI 接口（地点搜索/详情）**，与路况/路线同源、同一个 Key、合规最简、数据诚实可追溯。此决策同时是 10.11 目的地卡片的字段来源。

| 候选来源 | 结论 | 原因 |
|---|---|---|
| 高德 POI 搜索 + 详情 | ✅ 唯一 | 同源同 Key；返回名称/分类/地址/营业时间/评分/照片（rating/biz_ext/photos） |
| 高德周边搜索 typecode | ✅ 补充 | 同源，可生成"亲子/户外"等特色标签归类 |
| 百度百科/维基 | ❌ | 无开放 API、需爬取、版权风险 |
| 携程/去哪儿/马蜂窝 | ❌ | 无免费开放 API |
| 小红书 UGC | ❌ | 版权与合规不明 |

**使用纪律（配额约束，呼应 9.2）**：
- 锚点计算仍用县区中心 + 预置底库（Top200 人工维护），**不把 POI 查询当批量数据源**；
- 目的地详情**仅用户点击卡片时按需查询（1 次/点击）**，按 poiid 本地缓存复用；
- 双复用：POI 坐标可作为目的地锚点的候选坐标，一次请求服务信息展示与采样两处；
- 数据诚实约束：描述缺失显示"暂无更多介绍"、评分缺失隐藏、门票/开放时间缺失不展示——不填演示数据（守住第 2 条设计哲学与 7.3 下界）。

## 10. 前端设计要求

### 10.1 技术栈
- TraeCode 生成开发（Vue 或 React，由工具决定，不锁定）
- 高德 JS API：地图底图 + `AMap.TileLayer.Traffic` 官方实时路况图层（视觉参照层）
- 自有 Canvas 层：扇区扫描动画 + 县区聚合热力填色（官方图层不可定制，热力必须自绘）
- 分享卡：原生 Canvas 离屏绘制（不依赖html2canvas的跨域问题）

### 10.2 信息架构：地图即决策画布（单页三态，地图全程常驻）
以地图为**唯一主舞台**，用户全程盯着"自己在哪、哪个方向是绿的、推荐去哪"。前景控件（扫描钮/结果卡/对比条）随状态切换，但地图与数据层常驻在底层，形成"地图讲结论、文字补细节"的双通道呈现。

| 状态 | 地图上呈现 | 前景控件 | 核心动作 |
|---|---|---|---|
| ①定位态 | 底图 + **用户定位蓝点**；若本地有热力缓存则直接显示（返回/缓存命中时进入即见热力，视觉立刻有答案） | 品牌名 + 大按钮"扫一圈" + 手动选点入口 | 点击扫描 |
| ②扫描态 | 底图 + 蓝点 + **雷达扫描动画**（各扇区按真实指数逐个点亮红绿灯色，热力实时填充） | 扫描进度（可跳过） | 等待6~8s |
| ③结果态 | 蓝点 + **县区热力填色** + **推荐目的地锚点 pin（Top-n，色+编号）** + 相机飞至选中锚点 | Top-3推荐卡 + 对比条 | 点pin/卡片 → 详情 → 跳高德导航 |

> 设计意图：用户在**动手前就能一眼看到"东南一片堵、正北约一小时能到"**——热力+蓝点+候选 pin 在地图上同时存在，把"节省X分钟"从一行文字变成了可视的空间关系，视觉直接层叠最终决策。

### 10.3 视觉规范
- 深色地图底（贴合"临时起意、随时出发"的夜间/早间情境）
- **红绿灯语义色是全产品唯一的强饱和色**，不做第二套配色体系
- 品牌色克制（青灰+白），所有注意力让给路况数据
- 字体层级：推荐卡中"方向 + 节省分钟数"用最大字号——用户唯一真正关心的两个数字

### 10.4 交互细节
- 扫描动画**必须由真实数据驱动**：扇区颜色由该扇区真实指数决定，不是随机表演
- **地图=主舞台**：用户定位是一个固定蓝点，推荐结果以"蓝点为中心、绿的方位一目了然"呈现；定位/手动选点后蓝点与热力随防抖重绘
- **卡片 ↔ pin 双向联动**：点击结果卡 → 相机飞至该县区 + 高亮对应锚点 pin；点击地图 pin → 对应卡片滑到前台并高亮，二者互为入口（同编号同色）
- **热力即决策的反向直觉**：热力图填色=拥挤度（黄→红升温），推荐锚点 pin 用红绿灯语义色 + 编号标注"低拥堵方向"，冷门区显绿，与整体配色唯一体系一致
- 推荐卡横向滑动切换；点击后地图相机飞到目标县区
- "节省X分钟"带计数滚动动效（从热门方向ETA滚到错峰ETA），动效结束后地图相机飞到对应锚点
- 分享卡默认**大字版**（适配发家庭群的老年用户）：方向、县区、ETA三行大字

### 10.5 文案语气
- 不说教、不堆砌参数；像一个懂路况的朋友："北边现在很顺，过去只要40分钟，比去南边少堵1小时。"
- 理由句全部模板生成+人工润色，禁用LLM实时生成（避免不可控文案）

### 10.6 性能要求
- 首屏 < 3秒（定位 + 底图加载）
- 扫描态 6~8秒出结果，12秒超时强制返回已有部分结果
- API并发严格限流（QPS≤3），队列化

### 10.7 降级与异常
| 异常 | 降级方案 |
|---|---|
| 定位失败 | 城市/县区手动选择器 |
| 交通态势配额耗尽 | 提示"演示模式"，使用本地缓存数据并明确标注 |
| 路径规划失败 | 推荐卡仅显示方向与县区，不提供ETA |
| 网络全断 | 静态兜底页（产品说明） |

### 10.8 无障碍
- 拥堵信息**颜色+图标+文字**三重编码（色弱可用）
- 所有触控目标 ≥ 44pt

### 10.9 热力渲染规范（v2.3 新增，地图数据可视化的唯一法源）
> 目标：热力是一张**连续密度面**，不是贴纸；"哪里堵、哪里顺"一图可读，不靠猜。参考 Mapbox GL 核密度（heatmap-radius/weight）、ArcGIS bloom、Apple Maps HIG muted 强调样式及感知均匀色阶共识。

| 规范项 | 规则 | 实现 |
|---|---|---|
| 渲染模型 | 检查点为高斯核，**核密度连续面**（重叠区自然累积变亮），禁用孤立色块 | 多层 `radial-gradient` 叠加 + `mix-blend-mode: screen` |
| 色阶 | **红绿灯感知均匀色阶**：`绿#16A34A→黄#FACC15→橙#FB923C→红#E8463A`，0~100 连续插值，禁止彩虹断层 | CSS linear-gradient 插值 / Canvas 逐像素映射 |
| 双编码 | 密度=**亮度+颜色**双编码；高拥堵核心提亮（bloom 发光），边缘柔化 | blur + 高光核心层 |
| 行政区边界 | 县界细白线描边 + 内部淡填充（choropleth 辅助层），与结果卡县名对应 | 行政区 Polygon 渲染层 |
| 结果态收敛 | **扇区 conic 只用于扫描动画**；结果态隐藏扇区线，只留热力面 + 推荐 pin | 图层显隐切换 |
| 图例 | 热力图必有 scale 上下文：色带 + 数值（0~100）+ 档位标签，常驻地图角落 | 图例组件 |
| 推荐 pin | 绿色系 + 白色描边 + 绿光晕环，置于绿区内（"绿中选绿"） | pin 组件 |
| 色弱兜底 | 颜色之外补 icon/数字（承 10.8 三重编码） | 图层级 |

**与设计哲学的关系**：色阶方向"绿=畅通、红=拥堵"符合驾驶直觉（与高德/Apple 一致），并保留 2.2「红绿灯语义色是全产品唯一强饱和色」的克制原则——热力是唯一允许大面积使用语义色的图层。

### 10.10 缩放与时间预算联动（v2.4 新增）
> 目标：地图可自由缩放，但缩放始终服务"时间宽裕选远处、时间紧张选近处"的决策语义，不沦为随意划图（守 2.4 一屏一决策）。

| 设计点 | 规则 |
|---|---|
| 默认视野 | 以用户为中心、半径约 60km（与默认扫描半径一致） |
| 缩放入口 | 地图原生手势（双指/滚轮）+ 右下角缩/放按钮（拇指热区） |
| 时间预算滑杆 | 「今天能开多久」滑杆：30分钟/1小时/2小时/4小时，与地图缩放**双向联动** |
| 半径↔缩放映射 | 30分钟≈15km(zoom 10)｜1小时≈40km(zoom 9)｜2小时≈80km(zoom 8)｜4小时≈150km(zoom 7)（可微调） |
| 热力随视野 | 只请求**可视区**检查点（region-scoped 懒加载）；放大加密采样、缩小降采样；热力半径随 zoom 自适应 |
| 缩放限制 | zoom 5~13 区间，避免无意义全览 |
| 雷达扫描 | 扫描圈半径跟随视野/滑杆，"时间宽裕扫远处"语义自然成立 |

> 设计意图：缩放不是地图设置项，而是"时间预算"的可视化——拖滑杆地图自动缩到对应半径，手动缩放滑杆反向同步。宽裕者一眼望到 150km 外的方向，赶时间者锁定近处绿区。

### 10.11 目的地卡片（v2.4 新增，承 10.4 卡片↔pin 联动）
触发：点击推荐 pin 或 Top-3 卡片 → 底部升起**半屏目的地卡片**（不做独立详情页，保持轻量）。

信息层级（自上而下）：
1. 名称 + 分类标签（自然风光/亲子/古镇…）+ 高德评分
2. 距离 / 预计通行时间 / 方位（与雷达扫描语义衔接）
3. 一句话简介（来源 9.7 POI 描述；缺失显示"暂无更多介绍"）
4. 旅游资源块：开放时间、门票参考、特色标签、"冷门认证"话术
5. 操作：主按钮「去这里（导航）」+ 次按钮「分享卡片」（延续发家庭群场景）

约束：所有字段来自 9.7 单一数据源；缺失即隐藏，不填演示数据。

### 10.12 设计语言规范（v2.6 新增，基于 uicraft 细化，对照前期原型图）
> 目的：把 10.2/10.3/10.4/10.9/10.10/10.11 的零散视觉要求收敛为一套**完整、一致、可直接落地**的设计语言。对照前期结果态原型图（核密度热力 + 县界 + 图例 + pin 联动）与扫描态原型图（扇区雷达动画）提炼，确保"高审美 + 全产品一致性 + 开发可执行"。原则：苹果设计哲学的"安静高效"——系统不抢戏，数据做主角。

#### 10.12.1 设计原则（承第 2 章）
1. **安静高效**：界面元素全部让位于路况数据；克制到"界面消失、只剩决策"。
2. **一屏一决策**（承 2.4）：任何一屏只允许一个主决策动作。
3. **红绿灯语义色是全产品唯一强饱和色**（承 2.2/10.3）：视觉系统的最高原则。
4. **数据诚实可视化**（承 2.3）：颜色、数字、动画全部由真实数据驱动，禁止装饰性假数据。

#### 10.12.3 视觉系统细则
- **色彩使用规则**：强饱和色仅红绿灯三色 + 热力插值色阶（10.9）；品牌青灰只允许出现在 Logo 与次级按钮；文字不染色、按钮不做渐变、无"泛光科技感"装饰。
- **字体层级（Apple 字号步进）**：

| 层级 | 字号/字重 | 字体族 | 用途 |
|---|---|---|---|
| Hero 数字 | 44px Bold | --font-num | "节省47分钟"（结果卡最大字号，用户唯一关心的数字） |
| 标题 | 20px Semibold | --font-title | 方向/县区名 |
| 正文 | 15px Regular | --font-body | 简介/理由句 |
| 辅助 | 13px Regular | --font-body | 时间戳/边界声明（8.3） |
| 图例 | 11px Regular | --font-body | 热力图例档位标签 |

  - 数字一律等宽（ETA/距离/分钟数）防跳动错位；其余文本禁用等宽。
- **图标**：线性 2px 描边、圆角端点；仅功能指示（定位/分享/缩放/导航），零装饰性图标；SVG Sprite 单源复用。
- **卡片（毛玻璃三层，无阴影）**：
  - 底：`background: var(--color-surface); backdrop-filter: blur(8px) saturate(1.2);`
  - 边：1px `--color-border` 内描边（伪元素 inset 实现，替代投影）
  - 无投影（Apple 平层质感），层次靠 blur + 透明度
  - 推荐卡激活态：边框 1px `--color-success` + 同色左缘条
- **图例**：色带 + 数值（0~100）+ 档位标签，常驻右下角（承 10.9），`--color-surface-strong` 底压住地图干扰。
- **推荐 pin**：绿系实心圆点 + 白描边 + 绿光晕（`box-shadow: 0 0 12px var(--color-success)`），编号徽章同色反白。

#### 10.12.4 动效系统细则（全部真实数据驱动，承 10.4）
- **扫描动画**：扇区逐区点亮，每扇区时长 = `该扇区指数/100 × 800ms`（越堵点亮越慢，拥堵方向"看得见的沉重"）；全部点亮后热力面 300ms 淡入覆盖，视觉由"点状扫描"过渡到"连续密度面"（与 10.9 结果态收敛衔接）。
- **卡片滑动**：横向滑动阻尼，摩擦系数 0.8；边缘吸附阈值 ±10px 触发切换；切换 `--dur-card` + `--ease-standard`；到达边界回弹 60ms。
- **地图飞行**：点 pin/卡片 → `mapContext.animateCamera` ease-out 300ms，自动缩放至县区视图并居中锚点。
- **计数滚动**："节省X分钟"从热门方向 ETA 滚到错峰 ETA，`--dur-count` + `--ease-out`；滚动完成后相机飞行（编排次序：先数字、后地图）。
- **入场序列**：结果态三张推荐卡自底部错峰滑入（间隔 `--dur-stagger`），强化"扫描完成"的时刻感。
- **动效降级**：`prefers-reduced-motion: reduce` 时全部动画降为瞬移（数据照常显示）；扫描动画属"数据加载遮罩"，缩短至 1s 内但不取消。

#### 10.12.5 响应式断点（v2.6 新增）
| 断点 | 屏幕 | 适配规则 |
|---|---|---|
| < 360px | 小屏手机 | 字号降一档（Hero 36px）；卡片全宽、左右留白 12px；触控目标仍 ≥44pt |
| 360~479px | 主流手机（主场景） | 基准布局，间距按 16px 基准 |
| 480~767px | 大屏手机/折叠屏 | 结果卡可横向双排预览 |
| ≥ 768px | 平板/横屏 | 结果卡与目的地卡改**右侧浮层**（不压地图），地图占比扩大；扫描按钮保持右下拇指热区 |
| 全断点强制 | — | 触控 ≥44pt；热力半径/密度由 zoom 驱动（10.10）；字号用 `clamp()` 平滑缩放 |

#### 10.12.6 组件状态规范
| 组件 | 状态 | 规范 |
|---|---|---|
| 主按钮「扫一圈」 | 默认/按压/禁用/加载 | 胶囊、绿底白字；按压透明度 0.8；加载态文字→"扫描中…"；禁用灰（数据加载时） |
| 推荐卡 | 前台/后台/激活 | 前台 1.0、后台 0.92 缩放 + 压暗；点 pin 联动激活（绿边） |
| 推荐 pin | 常态/激活 | 激活放大 1.25 + 光晕增强 |
| 时间预算滑杆 | 常态/拖动 | 拖动时地图实时联动（10.10），松手吸附档位 |
| 降级提示 | warning | 黄条 + 图标 + 文案（"演示模式·数据为本地缓存"），不打断操作 |

#### 10.12.7 无障碍与一致性验收
- **无障碍**：三重编码（色 + icon + 文字）承 10.8；正文对比度 ≥ 4.5:1；热力图例数值作色弱兜底；所有可点元素 focus-visible 可见。
- **一致性自查清单**（发布前逐项核对）：
  - [ ] 全产品强饱和色仅红绿灯 + 热力插值（10.9 色阶），无第三套配色
  - [ ] 所有数字等宽、所有卡片同圆角同毛玻璃参数
  - [ ] 无装饰性图标/渐变/阴影（阴影仅允许 pin 光晕）
  - [ ] 文案语气一致（10.5），数字口径一致（8.3 边界声明）
  - [ ] 动效全部由真实数据驱动（10.12.4），无随机表演

#### 10.12.8 图层叠放次序（z-order 契约）
```
前景控件（按钮/结果卡/图例/滑杆）  --z-chrome 40 → --z-sheet 50（半屏卡）
扫描动画（仅扫描态）              --z-scanner 30
用户蓝点 / 推荐 pin               --z-pin 20
热力连续面 + 县界描边             --z-heat 10
高德底图 + 实时路况图层            --z-map 0
```
> 约束：热力面永远位于路况图层之上（路况作参照、热力作结论）；pin 高于热力但不高于前景控件；扫描动画结束后隐藏（10.9 结果态收敛）。

## 17. 合规与数据使用

- 高德开放平台数据仅限本应用内展示，**不得缓存后二次分发**（缓存仅限5分钟内技术用途）
- 页面标注"地图数据 © 高德地图"
- 不在服务端存储任何定位；详见下方定位合规口径
- 遵守《个人信息保护法》最小必要原则：无账号体系、无设备指纹、无行为埋点

### 17.1 定位合规口径（v2.1加强）
精确地理位置依《个人信息保护法》属**敏感个人信息**，需单独同意。处理方式：
- **仅当用户点击"扫一圈"时采集定位**，不进入页面即默认上报；采集仅用于本次扫描
- 定位**不存储、不上报**；一次请求用完即弃
- 页面提供一句话用途声明："定位仅用于计算你周围的方向，不会上传或保存。"
- 手动选点是完全的隐私替代路径（不依赖授权），作为默认兜底
